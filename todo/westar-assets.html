Westar — what the pk3 needs

The client code is done and the weapon works. These are the asset paths it looks for, taken straight out of the source. Everything here has a fallback, so nothing crashes if a file is absent — but you get the wrong gun, a silent shot, or a blank icon until it exists.

The one that matters most is westar34_left.glm — a mirrored copy of the world model. It is the only way to get a properly flipped pistol in the off hand, and it works on every renderer. Details in The mirrored model.

Both .glm files need a *flash tag/bolt — that is where the muzzle flash and the alt-fire charge sprite are drawn from. The .md3 view model needs the usual tag_flash, and the hands model the usual tag_weapon.

The mirrored model

The off-hand pistol has to be a separate, geometrically mirrored model. It cannot be done in code, and it is worth knowing why so nobody tries to "fix" it later:

Mirroring an object in a renderer means negating one axis of its transform. That flips the winding order of every triangle, so the front faces become back faces. The stock JKA renderer only corrects for that on portal mirrors, not on individual models — so a code-mirrored pistol renders inside out. Patching the renderer would fix it, but then the weapon would only look right for players running a modified client binary. A mirrored model works everywhere, with no engine change.

So: take westar34.glm, mirror it across its left–right axis, and export as:

models/weapons2/westar34/westar34_left.glm

Flip the normals on export. Mirroring geometry reverses face winding, so without this the model is inside out for exactly the reason described above — just moved from the renderer into the asset.

Keep the *flash tag. It carries over from the mirror, but check it survived — without it the off-hand gun has no muzzle flash and no charge glow.

Everything else about it is identical to the right-hand model — same skin, same scale, same name for the surfaces. The client loads it automatically if it is present.

If something is missing

Nothing crashes and nothing errors out — every path has a fallback, so the pk3 can be shipped in pieces. This is what each gap actually looks like in game:

MissingWhat you see instead
westar34_left.glm Off-hand pistol uses the normal model. Correct position and angle, just not mirrored — it faces the same way round as the right-hand one.
westar34.md3
westar34_hand.md3		 First person falls back to the blaster pistol — so you would see a blaster pistol in first person and a westar in third.
sound/jof/westar*.mp3 Falls back to the standard bryar pistol fire sounds. Audible, just not the westar's.
w_icon_westar* Blank slot in the weapon wheel and HUD.

Quick way to tell what is already in there: if first person currently shows a blaster pistol rather than a westar, then westar34.md3 is not in the pk3 yet. That is the fallback doing its job, not a bug in the code.

Checklist

  • westar34.glm — world model, has a *flash tag
  • westar34_left.glm — mirrored copy, normals flipped, *flash tag intact
  • westar34.md3 — view model, has tag_flash
  • westar34_hand.md3 — hands model, has tag_weapon
  • sound/jof/westarfire.mp3
  • sound/jof/westaraltfire.mp3
  • gfx/jof/w_icon_westar + gfx/jof/w_icon_westar_na

Loose files (not packed into a .pk3) need sv_pure 0 on the server to load — handy while iterating.
